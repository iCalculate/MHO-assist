# 方向序列助手

这是本机运行的窗口软件。选择任意窗口或框选屏幕范围后，软件通过图像自动定位箭头序列，输入方向键，并检查变黄反馈。

## 使用方法

1. 在 Windows 上按下方说明安装依赖，再运行根目录的 `start_assist.cmd`。已打包时可直接启动 `release_v5/ArrowAssist/ArrowAssist.exe`。
2. 从下拉列表选择目标窗口；或点「框选范围」，框住包含完整游戏画面的区域。
3. 点「启动预览」，切回游戏窗口，等待软件自动定位箭头区域。
4. 确认手动方向键能正常操作游戏，然后在目标窗口按 **F8** 开始自动输入。
5. **F9 暂停**，F8 也可切换启用/暂停。关闭助手停止运行。

框选范围需包含底部序列和右侧四个按钮，不必精确对齐游戏边界。框选中心应位于接收按键的窗口内，以便绑定输入目标。选择窗口模式跟随窗口移动和缩放；固定屏幕范围在目标移动后需重新框选。「窗口模式」可以退出固定范围模式。

工具发送普通电脑方向键事件。目标程序如何把方向键转换为游戏操作，沿用你的现有配置；若目标失焦后会关闭键盘映射，返回时需要重新启用。助手不识别目标软件名称，不连接手机、不读取 ADB、不修改目标配置。

## 识别与反馈

- 全部在本机运行，无需联网，不调用大模型。
- 先从图像里的四方向按钮自动定位游戏，再锁定底部序列区域。自动定位需要约数百毫秒；定位后最高约每秒 120 次捕获局部图像。
- 图案与颜色双重校验，同时要求完整序列的位置稳定至少约 60 ms，避免弹出途中提前输入。本视频中实测 3～7 个箭头；8～9 个槽位有预留但尚无真实视频验证。
- 从左到右快速输入，每轮只触发一次；序列消失至少 180 ms 后才允许下一轮。
- 输入后检查每个箭头是否变黄。1.5 秒内未全部确认则显示确认数量，本轮不重发，默认继续等下一轮；在「设置」中勾选「反馈未确认则暂停」可启用严格暂停。橙色的原始上箭头与黄色反馈作了区分。
- 只向前台目标窗口输入。失焦、暂停或关闭时中止剩余按键，为已按下的键发送抬起。
- 启动和预览不会自动按键。最好在新序列出现前按 F8；预览不会消耗本轮；在当前完整序列仍可见时按 F8，可以直接输入。实际发送过的同一轮不重复发送。

默认按住 30±4 ms、间隔 30±10 ms，每个按键分别随机采样，最短 5 ms。两项抖动可以分别设置为 0 关闭。修改参数后点「启动预览」应用。实际速度还受系统调度、投屏及手机响应影响。

自动定位与识别基于本视频的图案、四按钮布局和序列间距。其他界面、遮挡、过低分辨率或其他箭头风格需重新适配。新序列如果没有消失间隔，也需调整轮次判断。

## 验证与源码运行

从仓库克隆后，在 Windows 的项目根目录安装依赖并启动：

```powershell
python -m pip install -r requirements.txt
python assist.py
```

测试使用仓库中的界面裁图和相对时间数据。从项目根目录运行：

```powershell
python -m unittest discover -s tests -v
```

可用自己的录像做离线回放。触发时间、序列和耗时保存到 `analysis/replay.json`，逐轮裁图保存到 `analysis/replay.jpg`。算法耗时与手机端输入延迟是不同的测量。

```powershell
New-Item -ItemType Directory -Force analysis | Out-Null
python replay.py "path\to\recording.mp4"
```

打包时先安装 PyInstaller，再运行 `./build_windows.ps1 -ReleaseFolder release_v5`。复制发布版时请保留整个 `ArrowAssist` 文件夹及 `_internal`。

## 本次更新

- 输入条件：自动输入已启用、目标窗口在前台、整排方向及颜色有效并达到阈值、连续两帧相同、该轮尚未实际发送。新版会在状态栏显示阻止输入的原因。
- 即使未观察到消失间隔，连续三帧确认的不同新序列也可开启下一轮；相同序列仍要求观察到消失，避免同一轮重复。
- 高速区域定位成功后保持锁定，不因空白场景重新定位。位置和参数自动保存在 exe 同目录的 settings.json，重启后按目标程序和窗口标题匹配恢复。窗口等比例缩放会相应缩放；长宽比例明显变化则重新定位。
- 若布局变动或记忆位置错位，点「忘记当前位置并重新定位」。固定屏幕范围在游戏窗口移动后需重新框选。
- 框选使用每个显示器独立的截图与可见选框，按显示器实际坐标换算，支持屏幕缩放和负坐标。请在一个显示器内框选；Esc / 右键取消。

## V3：弹出动画与偏移修正

本地复现：原视频 35.600 秒的定位是 (340,375,447,49)，动画稳定后应为 (283,377,493,54)。旧版可在动画中锁定错误尺寸；横向仅偏 8 像素也会无法识别。

- 自动定位现在需要连续两次几何结果稳定，不保存第一次动画估计；整排箭头位置稳定后才记忆区域和允许发送。
- 高速区周围增加小幅捕获余量，联合检查所有箭头的同行排列和间距，支持区域小幅偏移；持续失配后用四个方向按钮自动恢复定位。
- 金色的已完成箭头仍计入槽位，不会把剩余后半段误当成一组更短的新序列。
- Windows 接受键盘事件不等于手机或游戏已接受。日志分开显示「已发送」和「已确认」。未确认时在 exe 同目录 diagnostics 保存发送前后箭头截图及 JSON，不保存整个桌面。
- 界面收紧至约 740×530；参数收进「设置」，日志按时间、状态和详情分列分色。长日志可悬停查看完整内容。

验证资料在 analysis/v3；视频回放和本地测试均不代表真实手机链路的端到端验证。

当前电脑的 QtScrcpy 输入修复版会在失焦后自动回到普通模式。回到投屏后，需按 Ctrl 重新进入映射模式，再用 F8 启用助手；F8 仅切换助手，不替代目标软件的映射开关。该行为已核对本机安装目录中的修复说明，助手本身仍支持任意窗口。

## V4：统计、运行历史、中英文和投屏联动

- 主界面的日志区域替换为统计面板。保留长条预览，窗口默认约 800×630；设置折叠，右上角切换中文 / English。
- 可切换「当次启动 / 全部历史」。同时显示本次新增与累计轮次、箭头数量。方向分布、最近十轮的按键构成、轮次置信度分布、最近 60 个采样段的识别耗时折线均可查看。悬停轮次柱可查看原始方向序列及各方向数量。
- 识别轮次按稳定整排序列计数，包含预览，不按帧重复计数。Windows 已发送、游戏变黄确认分别统计；平均置信度是图案匹配分数，不是按键成功率。耗时折线每半秒左右汇总图像算法调用，不含投屏、发送按键及手机响应。
- 历史从 V4 开始累计，旧版未保存完整轮次日志，不能补造历史。软件每次启动建立一个会话，重启预览不会清空当次统计。
- 数据统一保存在项目 data 文件夹，更新 release 版本不会清空它。logs/每次启动的时间戳.log 保存当次事件，logs/history.log 保存累计事件；history.sqlite3 保存查询数据，summary.json 保存当次及累计汇总。界面「历史 / 日志」打开日志目录。
- 「投屏工具」可打开输入修复版，自动关联唯一的 Phone 投屏窗口并启动预览（不自动启用输入）；F10 切回目标窗口。下拉菜单还可调用恢复游戏控制、按键编辑器、清理残留触点，以及游戏工具文件夹。
- 映射键从 Generic-Alt 配置读取，显示在设置及投屏工具提示里；无法由此判断投屏内部当前是否已开启映射，所以不自动切换，避免误关已有映射。恢复和清理工具由用户点击执行，不在后台自动调用。
- 桌面 Monster Hunter Outlanders 已集中游戏、QtScrcpy 修复版、恢复控制、清理触点、按键编辑器和助手等七个入口。助手快捷方式使用稳定启动器，后续发布无需再添加桌面快捷方式。

V4 验证图使用独立临时数据库和明确的 DEMO 数据，不计入用户历史。

## V5：自动连续刷与三轮步骤

主界面「连续刷」拨钮默认关闭。开启拨钮、启动预览后，切回目标游戏窗口并按 F8，才允许自动重开；F9 随时暂停，失焦时中断重开流程。正常方向输入仍沿用原来的识别和变黄确认。

已核对本地最近完整一局：30 组序列，共 171 个方向键，分为三轮，每轮 10 组；三轮序列长度分别逐步增加到 5、6、7。步骤根据稳定识别组数、长度变化及轮间间隔推断；中途接入或漏识别时，组数不一定刚好为 10。不会仅凭计数触发重开，还需识别出结算页或已回到可立即匹配页面，并确认不在跳舞界面。

重开顺序：单击并松开 Shift → 单击 [ → 单击 ] → 再单击 ]。每一步至少间隔约一秒，页面核验未完成时会延长等待。Shift 后需看到可匹配页面；若本来就在可匹配页面，会记录为「页面已就绪」，而不伪称发生了变化。[ 后需要匹配按钮所在页面消失；半透明弹窗后的暗化背景按钮不视为可匹配页面；] 后通过中央和左侧界面的分块像素变化检查页面变化，过滤小范围动画和噪声。

单步 6 秒未确认页面变化会暂停自动输入，不盲目重发；流程完成后等待新的箭头序列，确认下一局实际开始。90 秒仍没有下一局箭头则暂停。关闭再打开连续刷拨钮可清除流程错误，但仍需 F8 启用输入；如果停在中间弹窗，请先手动回到可匹配页面。

重开故障会保存所选游戏画面的前后截图至 data/diagnostics/cycle；页面变化比例、每次菜单键和流程结果记录到当次与累计 .log，以及 SQLite 的 cycles 表。菜单按键不混入方向键数量；完成局数按观察到的第三轮结束页面统计。

置信度分布重新划分为 <80、80–85、85–88、88–90、90–92、92–95、≥95 七档，既有历史数据也会按新档重新计算，不删除原始分数。

菜单操作依赖你当前 QtScrcpy 的 Shift / [ / ] 映射。页面模板基于本次中文游戏界面，布局或游戏语言变化需重新适配。自动流程已做历史、录像图像和模拟页面切换验证；这不等于手机端真实重开链路已完成实测。
